## Adapter mapping (SO-ARM101 onto the kit's sim-so101)

The bench's point ids (tool, wrist, elbow), frame (base_link) and joint names already match
the simulator. The links do not, so they are mapped:

| Bench link | Simulator link (so101_new_calib.urdf) |
|---|---|
| `gripper` | `gripper_frame_link` |
| `wrist` | `wrist_link` |
| `forearm` | `lower_arm_link` |

- Point links are mapped (link_map); point ids, frame and joint names are unchanged.
- tool: the bench says 'centre of the gripper fingertips, closed'; the URDF's gripper_frame_link is a fixed frame 98 mm along the wrist_roll axis toward the jaw tips (8 mm off the axis). Close to, not exactly, the bench's point; unmeasured on Bob.
- elbow: bench link 'forearm' -> lower_arm_link, whose origin is the elbow_flex joint frame.
- wrist: bench link 'wrist' -> wrist_link, whose origin is the wrist_flex joint frame.
- Start state: the kit's example kit config (start pose, tolerance_m 0.01), not Bob's. Before a search, the start pose must be clear of every zone by at least the reference gate's margin (tolerance_m / 2 + 8 mm = 13 mm); A3 and E4 use an explicit start-pose override (start_overrides) because the default start fails that.
- The elbow's keep_in (the cell box) contains every elbow position the arm can reach (400 random configurations, least clearance 70 mm), so no command can make the elbow violate it; position results test the tool and the wrist.
- The simulator has no table: the keep_in floor (z 0) is enforced only by the gate.
- Only the static patched envelope is searched: scripted events (an envelope update, a human approach, a STOP) are not simulated by be-falsify/1.
